AI agents got the keys. Fulcrum is the only door.

Adapty now lets AI agents change your paywall tests. Agents check results constantly, and that is exactly how fake winners ship. Fulcrum is an MCP server between the agent and Adapty: the agent reads everything, and every change passes statistics, a policy and a human before Fulcrum makes it.

Peeking ships fake winners

Check an A/B test every week and stop as soon as it looks significant, and you will call a winner in tests where there is no difference at all. An agent that checks every hour makes this mistake faster.

≈ 22%

fake winners with naive weekly peeking at p < 0.05 (simulation of 200,000 A/A tests, 15 weekly looks)

≈ 5%

fake winners with Fulcrum's calibrated stopping boundary, same tests

≈ $19k

extra revenue on the demo app from shipping a real winner at week 9 instead of letting it run (independent check: $17.5k)

How it works

No Adapty tool, no CLI, no token: the agent's only path to a write is Fulcrum.

The agent asks

It reads tests and verdicts through Fulcrum's tools, then requests a stop or proposes a new test.

Fulcrum judges

Only on the test's declared goal metric, at its horizon, against a boundary that is strict early and relaxes later.

Policy checks

Allowed placements, challenger weight, daily write limit and approvers, from a policy file. Every block cites its rule.

A human approves

On a local approval page the agent cannot reach. Only then does Fulcrum run the change through the Adapty CLI, and the ledger records it.

On 16 August one arm of the Settings test led with p just under 0.05. An agent peeking that week would have shipped it. The boundary that week was 3.32; the evidence was 2.00. By the end, the other arm was ahead.

"Fine, justify it with payer rate"

The test was set up to improve 30-day revenue per install. Switching metrics after the fact is metric shopping, and Fulcrum refuses it, whatever the wording, every time, and logs each attempt.

How we built it

Spec first, tests before code, and reviewers that didn't share our assumptions.

Spec → tests → code

Every rule is an acceptance criterion with a test named after it: 188 tests, including a named attack suite.

Independent reviewers

Fresh AI reviewers saw only the diff and the spec. One found the agent could approve its own request; one killed a demo scene of ours that didn't hold up.

Numbers checked twice

An agent with no access to our code re-computed every number from the raw data before it went on a slide.
